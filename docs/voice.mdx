# Voice

Since `@gemies/sdk` 15.0.0 ([ADR 0017](./adr/0017-voice-is-a-realtime-session-through-kaana.md)),
no surface uses the browser's or the operating system's speech recognition. Since
[ADR 0041](./adr/0041-voice-turns-are-delegated-to-the-turn-pipeline.md), a call's voice
is a front end only: every turn it hears is answered by the chat route, as a typed turn.

| Feature | Hook | What it does | Route |
|---|---|---|---|
| Voice call | `useVoiceRoom` (screen: `VoiceSession` / `useVoiceLauncher`) | A spoken conversation, full duplex; the voice detects turns, the chat route answers them | `GET /v1/voice/session` (WebSocket) |
| Dictation | `useDictation` (in `GemieComposer`) | The composer's microphone: one recorded clip becomes text in the draft | `POST /v1/audio/transcriptions` |
| Read aloud | `useTTS` | A message, spoken on request (unchanged) | `POST /v1/audio/speech` |

## Status

Gemies reaches Kaana's one canonical API (Kaana ADR 0003) through `@kaana.ai/sdk` and
`@kaana.ai/contracts` (the versions `packages/api/package.json` pins). `packages/api/src/lib/kaana/port.ts` is a narrow port
whose members are the `Kaana` client's own (function properties, so a mismatch fails
the typecheck); every shape is the SDK's and the contract's, none restated. It is
tested against `@kaana.ai/sdk/testing`: the same client against Kaana's own schemas,
checks and voice catalogue in memory, so a request the tests accept is one Kaana
accepts.
`lib/kaana/transport.ts` is the one place the client is constructed: the real SDK,
whose credential is Alia's Oxy service token with `aud: kaana.ai`, minted from the
same identity as every other Gemies call to Oxy. A process with no Oxy service
identity has no client, and then a call ends `realtime-unavailable` and dictation
answers `TRANSCRIPTION_UNAVAILABLE` — typed, never a stand-in.

A call opens a Kaana `live` session (Kaana ADR 0012). Production serves voice only
once Kaana serves a `live` line there (its phases K2–K5); until then a call ends
`realtime-unavailable`. What is left is in [What is left](#what-is-left).

## A call

```text
app / SDK ──WSS /v1/voice/session──▶ Gemies API ──@kaana.ai/sdk realtime.connect (kind: live)──▶ kaana.ai/v1/realtime ──▶ voice
  PCM16 24 kHz binary frames             │   persona, credits per minute, typed errors
  + Gemies' JSON events                  │
                                         └─ delegation.requested ──▶ POST /alia/chat (loopback) ──▶ the typed-turn pipeline
                                            delegation.reply ◀── the answer, sentence by sentence
```

Gemies is the only client of the Kaana session. The device sends microphone audio and
receives the voice's audio, transcripts and a few events for the call UI; it never
sees the persona, a tool's arguments or its result. Gemies connects under its service
token (`aud: kaana.ai`) with the person as delegated attribution (`onBehalfOfUserId`):
lane `service_token`, relationship `alia-kaana`.

### The socket

`lib/voice/voice-socket.ts` mounts `GET /v1/voice/session` with `ws` in `noServer`
mode on the shared HTTP server, through the one upgrade router (`lib/websocket-upgrades.ts`), so socket.io's
handshake is never stomped. The protocol is `lib/voice/protocol.ts` (the SDK keeps its
own copy in `src/lib/voice-protocol.ts`; `VOICE_PROTOCOL_VERSION` makes a mismatch a
refusal):

```text
client: auth { token, appAssertion? }        an Oxy session of Oxy's own apps, and the app it is in
gemies: auth.ok
client: session.start { protocol: 2, conversationId, agentId?, voice, locale }
        | session.resume { protocol: 2, voiceSessionId, afterSeq }
gemies: session.accepted { voiceSessionId, callId }     still connecting
gemies: session.ready { model, maxDurationMs, … }       Kaana created the session
client: <binary PCM16 24 kHz mono, ~40 ms frames>
gemies: input.ready                                     the first frame was appended
gemies: user.speech_started / user.speech_stopped (when the voice reports them),
        transcript.delta|done { role, messageId, itemId }, <binary [u8 n][item id][PCM16]>,
        tool.started / tool.finished { messageId, name }, assistant.done, messages.saved,
        session.warning { ending-soon }, session.reconnecting, session.resumed,
        error { code, retryable, reference }, session.closed { reason }
client: session.end, auth { token, appAssertion? } (refresh)
```

Every event after `session.accepted` carries `seq`, which is what a resume replays
from. **Only a person's session is accepted**; an `oxy_sk_` machine credential is
refused with `credential-not-supported`. The SDK re-sends the app assertion with every
token refresh: it lives five minutes, and a call's turns carry it to the chat route.

### Opening, in order

`lib/voice/call.ts` (`VoiceCall.open`). **Never in a group** (ADR 0025): a call has one
gemie and a group's turns are its members', so a call there would answer as Alia and
write her transcript into their conversation. It is refused first, as `agent-unavailable`,
and `GemieChatContent` offers no call there. Then:

1. The turn's inputs from the identity — entitlements and the gemie — through
   `prefetchTurnInputs` (`lib/chat/turn-inputs.ts`), the same reads a typed turn makes.
2. **`voice-mode` is enforced by the server** (`plan-required`), not only by the app.
3. The gemie: one the person can open (`loadTurnAgent`), from the app the call is in
   (a gemie Oxy confines elsewhere is `agent-unavailable`, ADR 0021).
4. The line, from the catalogue (below). None: `realtime-unavailable`.
5. The first credit block (below). Refused: `credits-exhausted`.
6. **One call per person** (below): this call takes over any other.
7. The persona, from the gemie, the language and the stored conversation.
8. Kaana. The client stays `connecting` until `session.created` (`session.ready`).

### The line is the catalogue's default

`liveVoiceLines` (`lib/models/voice-models.ts`) reads Kaana's catalogue at open: the
active line whose `capabilities.realtime.defaultKinds` names `live` (Kaana ADR 0012 §4)
first, then every other active `live` line over `websocket` that takes 24 kHz PCM16, in
the catalogue's own order. Gemies names no model and ranks none by price: which
provider speaks is one reviewed change of `defaultKinds` in Kaana's catalogue. The voice
is the line's catalogue voice of the product gender (`male` | `female`); a line without
one is passed over. The upstream voice id is sent to Kaana and never shown or returned.
A later line is tried only when the model itself refused the open (`model_not_found`,
`unsupported_modality`, `no_route_available`, `invalid_request` on `voice`/`config`);
authentication, credit and rate refusals fail at once. The served revision
(`session.created`) is what the call's minutes are priced with and what `chat_analytics`
records (`platform: 'voice'`). Model and publisher names may be shown; the operator never.

The person's power level does not pick the line: the turns follow it like any typed turn.

### What the session is opened with

`kind: 'live'` and:

- **`instructions`: the persona only** (`lib/voice/persona.ts`): who speaks, from the
  identity guard (`buildVoiceIdentity`, the same identity a typed turn states), a
  speaking style, the person's language and the recent conversation as text, within the
  contract's 32 768 characters (the history shrinks to fit). No backend instructions and
  no tools reach the voice.
- **`voice`**, `pcm16_24khz` both ways, `turnDetection: server_vad` (the voice decides
  when a turn ends), `inputAudioTranscription { language }` in the person's BCP 47
  locale, and `delegation { acknowledgement: 'auto' }`, so the voice says a short "one
  moment" while a turn is answered.
- **Limits** (Gemies product rules, not capacity): 30 min, 2 min idle, audio bytes for
  30 min each way.

### Every turn is the chat route's

`delegation.requested { delegationId, text }` carries the person's words since the last
turn, assembled by Kaana. Each one is one turn of the conversation through `POST /alia/chat`
(`lib/voice/delegated-turn.ts`), asked over this process's own loopback port so it is the
very handler a typed turn and a Telegram person turn reach, middleware included: the
person's session and the app's assertion, the same gemie, `ToolPipeline`, memory, skills,
model selection through Kaana, credits and rate limit. The request is the SDK's for a
typed turn — the stored history with its ids plus the person's words, `assistantMessageId`,
a `turnId` — with `responseMode: 'voice'`, so `prompts/voice.md` shapes the answer for
speech. There is no voice brain and no voice tool list.

The answer streams back as `delegation.reply` (`lib/voice/speech-chunks.ts`): one chunk
per sentence, markdown dropped, the last one `final: true` (the latest complete sentence
is held until the next begins or the answer ends, because only the end says which is
last). Each chunk marks its numbers, times, prices, phone numbers, codes, emails, URLs
and names as `verbatim` spans — exact substrings, at most 32 — which the voice says
exactly (Kaana ADR 0012 §9.2). While a tool runs the device gets `tool.started` /
`tool.finished` with its name, and the voice a silent `delegation.context`.

- **Supersession.** `delegation.superseded` aborts that turn's signal and stops it the
  way the app's Stop does (`POST /v1/chat/turns/:id/cancel`). Words the stop kept from
  being stored open the next turn; a tool that already ran is reported by it, never
  retried. Each turn waits for the one before it to settle (5 s at most) before it reads
  the conversation, so the history it sends is the one stored.
- **Failure.** A turn the chat route refuses or fails is a typed failure: the voice is
  told in silent context that it could not be answered (so it can say so in its own
  words) and the delegation is dropped (`delegation.cancel`). Nothing is stored, and
  never a filler answer. The call goes on.
- **Hang-up.** The answer being given finishes and is stored, as a typed turn's does
  when its client goes away.

### Messages

The chat route stores the person's words (`text`) and the answer, as it stores a typed
turn's, before it ends its stream; the call then sends `messages.saved`. There is no
second writer. Every `transcript.delta|done` and `tool.started|finished` names
`messageId`, the id the message is stored and announced under: the person's transcript
names the user message the next turn stores, the voice's transcript and the turn's tools
name the answer. The client draws one message per `messageId`, so the stored copy is the
message already on screen. The voice may paraphrase; the stored answer is the chat
route's text. That wire is protocol 2; a protocol-1 client is refused with
`invalid-request`.

### One call per person

`voice_calls` (`db/schema/voice.ts`, migration `0094_voice_calls`) with a partial unique
index on `oxy_user_id WHERE status = 'active'`. `lib/voice/call-registry.ts`:

- A start takes over in one transaction under
  `pg_advisory_xact_lock(hashtextextended('alia:voice-call:' || user, 0))`: the
  active row ends `moved_elsewhere` (live lease or not) and the new one is inserted.
- Same task: the old call is hung up directly. Another task: `takeover` on the Redis
  channel `alia:voice-call`. Without Redis, the 10 s lease renewal that matches no
  active row hangs the old call up — the worst overlap is one renewal, and it is
  billed.
- The old device ends with `session.closed { reason: 'call-moved-elsewhere' }`, a
  reason, not an error. Dictation is not a call. A resume is the same call.

### Reconnection and ending

- **Client ↔ Gemies:** a dropped socket keeps the call for 30 s and the last 500 events;
  `session.resume { afterSeq }` replays them. Sticky routing on the ALB brings the
  resume to the task that holds the call; a peer task relays it otherwise
  (`lib/voice/peer-relay.ts`).
- **Gemies ↔ Kaana:** `RealtimeSession.resume()` within Kaana's window; if that fails, or
  Kaana's task shuts down, a new session on the same line under the same call, with a
  fresh persona from the stored messages (twice at most); the old session's turns are
  stopped. The client shows `reconnecting`, never `listening`.
- A call ends on hang-up, the screen losing focus or changing conversation or account,
  `call-moved-elsewhere`, `max-duration` (with a warning a minute before),
  `idle-timeout`, `credits-exhausted`, a typed error, or `server-shutdown`. Each
  closes the Kaana session (which settles exactly once), settles the credits and ends
  the row.

### Typed failures

Every failure of the call is `error { code, retryable, reference }` and then
`session.closed` — the realtime `failTurn`. Never a spoken "sorry" made up by Gemies,
never text nobody said. Kaana's errors are recognized by their public `code`
(`kaanaErrorOf`), so the real SDK's classes and the fake's read the same:

| Error | `VoiceErrorCode` |
|---|---|
| unavailable, no line, Gemies' credential refused | `realtime-unavailable` |
| rate, balance, spend, quota | `realtime-limited` |
| invalid or permission | `realtime-rejected` |
| provider failure, lost connection, contract violation | `realtime-failed` |
| Gemies' own | `plan-required`, `credits-exhausted`, `not-authenticated`, `credential-not-supported`, `agent-unavailable`, `resume-unavailable`, `invalid-request` |
| the device (SDK) | `mic-denied`, `mic-unavailable`, `connection-lost`, `voice-unavailable` |

A failed turn is not a failed call: see [Every turn is the chat route's](#every-turn-is-the-chat-routes).
The app says each code in its own language (`voice.errors.*`, `voice.ended.*`).

### Credits

A call is a paid-plan feature (`voice-mode`). The **voice minute** is the line's
catalogue `pricePerMinute`, silence included, metered by `VoiceCreditMeter`
(`lib/voice/credits.ts`) and converted with `creditsForCost`: a block of five minutes is
held at open, the next one a minute before the held one runs out; a refused block ends
the call with `credits-exhausted` after the turn being answered. **Each turn is a typed
turn** and is charged by the chat route as one. The call's duration ceiling stays Oxy's.
Gemies sets **no** concurrency or spend cap of its own: those are Oxy Console policy.

The backend constructs `kaanaForOxyService` once per voice call or dictation
operation, with the authenticated person's immutable inference attribution.
Attribution does not authorize private user data or change the workload's payer. The
client is disposed when the operation finishes, including failed calls.

### The production canary

`production-voice-canary.yml` (`workflow_dispatch`, main only) runs
`packages/api/dist/scripts/production-voice-canary.js` as a private ECS one-shot of the
exact live image, like the chat canary: it starts that image's API and enters its
loopback `/alia/chat` as the QA account through Alia's workload transport and the QA
account's Oxy automation task (`ALIA_CANARY_OXY_USER_ID`, `ALIA_CANARY_OXY_TASK_ID`).
It drives the production `VoiceCall` with the production environment one layer below
the socket, whose `auth` admits only a person's own session. It streams a recorded
request for a reminder (`src/scripts/fixtures/voice-canary-reminder.pcm`, 24 kHz PCM16
mono) in real time, then silence, and passes when the voice handed over a turn, exactly
one turn was answered and stored and it called `createAutomation`, the answer was
spoken, and the call settled (Kaana's usage, the minutes charged, the `voice_calls` row
ended `hangup`). It then stops the reminder as `DELETE /automations/:id` does and removes
its conversation. The one result line is `ALIA_VOICE_CANARY {json}`: the call id, Kaana's
session and request ids, the line, counts and settlements, never the QA identity, the
prompt or the answer.

### The client

Own HTTP speech and dictation use the shared Oxy linked transport. An audio
operation binds to core's session epoch: token rotation can continue, but an
account or operator change aborts the response body and closes an active voice
socket. The WebSocket authentication frame rereads that same bound session after
asynchronous application attestation. Signing out never reconnects an old call
under another account. HTTP requests omit cookies and reject redirects; explicit
external token callers retain their existing separate credential path.

`useVoiceRoom` (`@gemies/sdk/voice`) runs the socket (`src/lib/voice-call.ts`) over
an audio-engine seam (`src/lib/voice-audio-engine*.ts`):

- **Web:** `getUserMedia` with echo cancellation, noise suppression and gain control;
  an `AudioWorklet` that downsamples to 24 kHz PCM16 and a second that plays a
  jitter-buffered queue, in one `AudioContext`. Firefox now has calls.
- **iOS / Android:** `react-native-audio-api` (0.13.6), capture and playback in one
  engine; iOS session `playAndRecord` in `voiceChat` mode. **It needs a new native
  build** (config plugin in `app.json`), and Android's echo cancellation is not
  engaged by this version (no `voiceCommunication` input preset) — a release gate
  (below).

States are honest: `connecting` → `listening` **only** after `session.ready`, the
engine's first captured buffer **and** `input.ready`; `user-speaking`, `thinking`,
`using-tool`, `speaking` (when the first frame actually plays), `reconnecting`,
`ended { reason }`, `error { code }`. Levels come from the real buffers; no state is
inferred from a timer. Mute stops sending audio.

The call is part of the SDK's conversation screen (`GemieChatContent`, so the sheet,
`GemieChatScreen` and the app alike): the button, the bar, the notices (failure, moved to
another device, time limit) and the transcript. `VoiceSession` says what happened through
`labels` and `onNotice`; `useVoiceLauncher` owns the gate (`canStartVoice` /
`onVoiceBlocked`), the end of a call that stops being the screen's (`owner`, `isFocused`)
and `onCallEnded`. The app only answers them (`features/chat/runtime/use-app-voice.ts`:
its API, the voice and `speechLocale()`, plan and credits, what to refresh on
`messages.saved` and at the end) and supplies the catalogue
(`features/voice/ui/voice-labels-provider.tsx`).

## Dictation

`POST /v1/audio/transcriptions` (`routes/v1/audio.ts`, `lib/voice/transcribe.ts`):
multipart `file`, `language`, `durationMs`. Batch, not a streaming session. The model
is computed — `audio_transcriptions`, the clip's media type, the language, the cheapest
per audio millisecond — and tried at most three times, only on a model refusal.

- **Free on every plan**, the free one included: no plan feature, no credits (its cost
  is Alia's internal cost centre, ADR 0005). A person's session only; an `oxy_sk_` is
  refused (`CREDENTIAL_NOT_SUPPORTED`). Bounded by the 5-minute clip, Kaana's 20 MiB
  and the `/v1` rate limit.
- Typed answers: `TRANSCRIPTION_UNAVAILABLE` 503, `TRANSCRIPTION_LIMITED` 429,
  `TRANSCRIPTION_REJECTED` 422, `TRANSCRIPTION_FAILED` 502, `CLIP_TOO_LONG` 413,
  `INVALID_REQUEST` 400. Never partial or invented text.
- The clip lives in memory for the one request; nothing is stored.

`useDictation`: web `MediaRecorder` (`audio/webm;codecs=opus`, or `audio/mp4` on
Safari) with a real level meter; native the `expo-audio` recorder (m4a → `audio/mp4`).
States `idle` → `requesting-permission` → `recording` (only once the recorder started)
→ `transcribing` → `idle`, or `error { code }`. The remaining time shows in the last
30 s and the recording stops at 5 minutes. A failed transcription keeps the clip for
one retry. Dictation and a call never record together: the call bar replaces the
composer.

**An app with its own recorder** sends its clips with `@gemies/sdk/dictation` (SDK
22.6.0): `requestTranscription` and `DictationError`, the same request `useDictation`
makes, from an entry that reaches no React, native module, recorder or Oxy client. Astro
records in its browser shell and cuts the recording at pauses, so each phrase is one
request; a person's dictation is therefore several requests against the `/v1` rate limit
and the `alia-kaana` capacity (5 000 requests a UTC day for all of Alia's inference,
`~/Oxy/oxy/docs/inference/kaana-grants.md`).

**Live in production since 2026-10-16.** The chain Alia → `kaana.ai/v1/audio/transcriptions`
→ Oxy's `alia-kaana` `audio_transcriptions` terms (300 000 ms, USD 0.05 a request) → xAI
`grok-voice-transcribe-2.0` or Groq Whisper is deployed: Oxy has admitted
`audio_transcriptions` grants since 2026-10-16 03:22 UTC (the ones before were
`no_route_available` until Kaana's transcription lines were sold), and Alia's own
verification run that day transcribed a spoken clip on
`x-ai/grok-voice-transcribe-2.0@observed-2026-10-16`. What is still open is the device gate
in [Native validation](./native-validation.mdx#9-voice-through-kaana-to-validate).

### Streaming dictation (ADR 0024)

`GET /v1/audio/transcriptions/stream` (`lib/dictation/socket.ts`, `lib/dictation/stream.ts`,
protocol `lib/dictation/protocol.ts`): word-by-word dictation as a Kaana `transcription`
session. A `WebSocketRoute` of the one upgrade router.

```text
client: auth { token }                                     a person's Oxy session
client: dictation.start { protocol: 1, language?, sampleRate: 24000 }
client: <binary PCM16 LE mono 24 kHz>                      held while the session opens
alia:   dictation.ready { maxDurationMs }
alia:   transcript.interim { segment, text }               the segment's provisional text, whole
alia:   transcript.delta { segment, text }                 locked text, appended
alia:   transcript.final { segment, text }                 the segment's text; the only text kept
client: dictation.commit                                   end the segment now (push-to-talk)
client: dictation.end                                      no more audio
alia:   error { code, message, retryable }, dictation.closed { reason }
```

- **Who and what it costs.** A person's session only; an `oxy_sk_` is refused
  (`CREDENTIAL_NOT_SUPPORTED`). Free on every plan, like batch: no plan feature, no
  credits. One dictation is one `/v1` rate-limit request at open
  (`TRANSCRIPTION_LIMITED`, retryable, over it) and one Kaana grant.
- **The Kaana session.** `kind: transcription`, `pcm16_24khz`,
  `inputAudioTranscription { language, interimResults: true }`, `server_vad` with
  `createResponse` and `interruptResponse` false (Kaana's silence default), 5 minutes,
  30 s idle, the bytes of 5 minutes. The model is computed
  (`rankTranscriptionSessionCandidates`): an active line whose
  `capabilities.realtime.sessionKinds` includes `transcription`, over `websocket`, taking
  24 kHz PCM16, cheapest minute first; no line is excluded for its language. At most two
  candidates, the second only on a model refusal.
- **Segments.** Kaana's items become Alia's segments, numbered from 0 in order; the device
  never sees an item id. A segment's `transcript.final` is Kaana's `transcript.done`, trimmed,
  and replaces what the segment showed; nothing of a segment is sent after it.
- **Ending.** Kaana ends a session at once on `session.close`, so `dictation.end` first
  commits the open segment and waits, at most 3 s, for its final, then closes the session.
  Kaana's `max_duration` and `idle_timeout` end the dictation with that reason; its fatal
  errors map to the batch route's codes (`transcriptionFailureForCode`). A device that goes
  away closes the Kaana session.
- **Privacy.** Audio and text pass through; logs carry the dictation id, the model, codes,
  segment count and audio milliseconds.
- **The SDK.** `openDictationStream` on `@gemies/sdk/dictation` (22.8.0) speaks it; the
  API's `protocol.test.ts` holds the SDK's copy of the protocol equal to the server's.
  `useDictation` still records a clip for batch; adopting the stream there is the follow-up.
  Batch `POST /v1/audio/transcriptions` stays the fallback.

## Read aloud

Unchanged by ADR 0017: `POST /v1/audio/speech` in the product voice, `male` or
`female` (no upstream voice name is ever sent or shown), through
`lib/synthesize-speech.ts`. A call does not use it: the `live` session's voice speaks.

### When speech fails

The route answers a typed code with a provider-neutral, fixed message:

| Route answer (`error.code`) | Status |
|---|---|
| `SPEECH_UNAVAILABLE` — no inference client, no speech model, no route, storage not set up, Oxy refusing Alia's authority | 503 |
| `SPEECH_LIMIT_REACHED` — rate limit, quota, spending limit, balance (`Retry-After` when Oxy gave one) | 429 |
| `SPEECH_REJECTED` — the model refused the voice, the speed or the text | 422 |
| `SPEECH_PROVIDER_FAILED` — upstream error, timeout (504), transport, not MP3 | 502 / 504 |
| `SPEECH_GENERATION_FAILED` — storing or attaching the clip failed | 502 |

The route's message is provider-neutral and fixed per code; Oxy's `requestId`
travels with it. On the device, `requestSpeechClip` throws a `SpeechClipError`
that keeps the HTTP `status`, the typed `code` (`null` for a network failure or
a code the SDK does not know), `retryable` and `requestId`.

**Server side**, `lib/synthesize-speech.ts` is the only caller of the inference
client for speech and the only reader of its error type; the route and the show
pipeline see a `SpeechSynthesisError`. It tries the speech models in the
catalogue's order ([Model abstraction](./model-abstraction.mdx)) and moves to
the next — at most three, within one 60-second budget — only when the model
itself refused (`invalid_request`, `unsupported_modality`, `model_not_found`,
`no_route_available`, `commercial_permission_denied`); every other refusal,
authentication and credit above all, fails at once. Each failed request is one
structured `speech` log record — `code`, `reason`, `status`, Oxy's
`upstreamCode` / `upstreamStatus` / `requestId` / `param`, the models tried,
the product voice and the input's length — and never the text, the user or the
conversation. Each fallback is a `warn` record of the same kind.

### A clip is made once

Speech is paid per character, so `POST /v1/audio/speech` never synthesizes the
same thing twice for the same person (`lib/speech-clips.ts`). A reply read aloud
again — here or after a reload — is answered from storage, without calling Oxy.

**The key.** `speech_clips.cache_key` is a SHA-256 of
`[key version, oxy user id, speech model, voice, speed, "mp3", exact text]`.
The person is in it, so a clip is never shared between people: how fast an
answer comes must not tell one person what another had read aloud. The text is
taken exactly (no trimming or case folding) and is not stored. The speed is
rounded to two decimals, and `1` counts as no speed at all — that normalized
value is also what synthesis is sent, so the key describes the request made.

**The model.** A clip is keyed by the model that made it. Before synthesizing,
the request is looked up under every model `synthesizeSpeech` would try, in its
order (from the cached catalogue, no inference call), and the best-ranked stored
clip answers. A fallback therefore pays once: if the first model always refuses
this voice or speed, the second model's clip answers every later request. A
model that has left the candidates is never served; a new first model is used
for text that has no clip yet.

**A saved message.** `conversationId` + `messageId` must name the person's own
message (404 before anything is made otherwise). The clip is then filed under
that conversation — the first conversation that asks claims a clip that has
none, and it is never moved. `messages.audio_url`, which held one clip per
message whatever its voice or speed, is gone (`0093_drop_message_audio_url`,
post phase); the client always asks the route, and a stored clip is an instant
answer. `requestId` is in the answer only when that request made the clip.

**Two identical requests at once** are joined inside one API task: one
synthesis, and it is cancelled only when every request waiting for it has gone.
Across ECS tasks there is no lock: two tasks can each pay once for the same clip
in the same moment; the index keeps the first object and the other task deletes
its own. A clip whose synthesis has finished is stored even if the person has
left, so the next request is a hit.

**Where clips go.**

- Deleting a conversation (`DELETE /conversations/:id`) or clearing it
  (`DELETE /conversations/:id/messages`) deletes its clips first — rows and
  objects in one transaction, so if storage refuses the request fails with the
  thread intact and can be repeated.
- A clip unused for 30 days (`SPEECH_CLIP_RETENTION_DAYS`; every hit restarts
  the clock) is deleted by an hourly sweep on the leader task. This is what
  collects the sentences the retired on-device call loop had read aloud, which no
  saved message asks for, and the clips `messages.audio_url` held, which `0093`
  hands to the sweep already expired.
- Alia has no account-erasure path today. When it has one, a person's clips are
  their `speech_clips` rows and the objects under `<env>/tts/<oxy user id>/`;
  the sweep bounds them meanwhile.

The `speech_clips` row is the truth about its object: only `lib/speech-clips.ts`
deletes `tts/` objects. The media bucket has no lifecycle rule, and none may be
added on `tts/` — it would leave rows answering with links to nothing.

**Observability.** Every served clip is one `speech` `info` record, `Speech
clip served`, with `cache: "hit" | "miss"` (`miss` is a paid synthesis),
`inflight` (answered by another request's synthesis still running), the model,
the product voice and the input's length — never the text, the user or the
conversation. Each sweep logs `Speech clip sweep complete` with the clips and
objects removed, the empty runs included.

## Privacy

**Audio now reaches Alia, Kaana and the serving provider** — for a call, the
microphone stream; for dictation, the recorded clip. Alia logs no audio and no
transcript content (codes, sizes, durations and model ids only). The browser's and
the operating system's recognizers are no longer used: Chrome no longer sends a
dictation to Google's recognizer.

## What is left

- **Calls need Kaana to serve `live`** (Kaana ADR 0012 §8): the GPT-Live adapter and its
  catalogue line with `defaultKinds: ["live"]` (K2), Grok's emulated delegation as the

- **The device release gates:** Chrome echo cancellation with Web Audio playback
  (fallback: an `RTCPeerConnection` loopback), Android echo cancellation with
